# MiniMax H3 Cloud + 优云 GPU + Codex

把用户的 Mac 当作控制端，把 MiniMax H3 推理放在优云智算 GPU 上。默认使用 `scripts/resolve-plugin.sh` 解析的 `h3-community-cloud` 本地增强版，运行器随本 Skill 放在 `runtime/h3-community-cloud/`，使用相对路径解析，无需原作者本机路径；这不表示插件已安装到 Codex 市场。原 `minimax-h3-cloud` 保留为显式回退。云端操作通过官方 `compshare --json` CLI；常规生成不改源码，用户明确要求开发或修复时可在独立项目中修改并验证，不手写平台 HTTP 请求。

## 首次使用：先注册云 GPU，再安全接入

没有自己的已验证凭证的新使用者，先执行本节；本节优先于后面的素材流程和内置插件的首次选卡顺序。

1. **注册云 GPU**：说明本 Skill 使用优云智算，提供[注册／登录入口](https://console.compshare.cn/)。首次只请使用者完成注册，回来回复“已注册”；不要求现在租卡、充值或提交素材，不把全部技术步骤一次性展示。账号、验证码由使用者本人处理。明确已有账号时跳到下一步。
2. **助手准备接入环境**：注册完成后，按 references/setup.md 检查并补齐 Node.js、FFmpeg、官方 CompShare CLI 和随包运行器。已可用的依赖不重装。提供[API Key 管理入口](https://console.compshare.cn/uaccount/api_manage)，说明公私钥只在使用者自己的电脑录入。
3. **本人隐藏输入凭证**：请使用者在自己的交互式终端执行 `compshare config set --name h3-user --no-activate`，按官方隐藏输入录入公私钥，完成后只回复“已完成”。不把密钥发到聊天、不作为命令行参数、不写入 Skill 或 Git。不要读取凭证文件。若同名配置已存在，通过 CLI 配置清单确认是否复用或另取名称，不覆盖原有配置。
4. **由助手验证接通**：使用选定名称执行 `compshare --json --profile h3-user doctor`，再使用官方只读接口核验账户可访问区域。只报告是否接通及下一步，不回显凭证。成功才说“优云智算已连接”；失败依据脱敏错误定位，不用付费生成测试凭证。
5. **进入制作流程**：接入后再审查素材、生成提示词、确认输出规格，随后查询 H20/A800 库存和报价、建立无密钥且 resourceId 为空的运行配置。取得本次费用授权后才启动收费资源。已有账号和有效凭证的人只复核连接，无需重复注册。

## 当前增强流程与证据

- 2026-09-07：公开版附带增强版 0.2.1，核心生成代码与实机验收的 0.2.0-rc.2 相同。项目回归 24/24、包内 23/23 通过，插件与 Skill 格式校验通过。上传准备使用文件支持的 Blob，原子写入任务清单，保存实际工作流和阶段耗时。该内存优化不是 GPU 推理加速结论。详细证据位于解析出的插件根目录 VALIDATION.md。
- 正式创建或启动 GPU 前，在拟执行的 generate 命令追加 `--dry-run`。它读取本地配置和素材，不访问云端，检查参考标签、时长、格式、种子与工作流；不能替代实机验收。
- H20 单参考视频完整实机验收已通过：5 秒、16:9、0.2MP 方块平移案例输出 608×352、24fps、5.167 秒，带 AAC 双声道。26 个采样帧均有主体且无反向位移；Kimi 对五张代表帧未发现明显畸变、重复主体或平台水印。只提交一次，GPU 已停止。更多视频、多图混合、复杂人物/车辆、长视频和完整 2K 尚未由本次试验验证。
- 默认配置 `~/.config/h3-community-cloud/config.json`，结果 `~/.local/share/h3-community-cloud/outputs/`；Node.js 至少 22.17。已有任务继续使用它自己的 `--config`，不覆盖或迁移旧配置。
- `status` 的 `missing` 表示当前凭证可见范围内缺少历史实例，`unconfigured` 表示未绑定；认证、网络错误不能当作缺失。不得据此宣称其他实例或磁盘全部清理。
- 实例创建前报价与创建后实际费率可能不同；必须比较实际总价和当次授权上限。计划与实际费率可能存在差异，超出当次授权时必须停止并让使用者确认，不能套用发布者的费用授权。
- 参考视频验收失败时，仍保留已验证的增强流程与 H20 选卡能力，只将参考视频具体失败边界写明。各项能力按验证证据独立标注，不把一次失败扩大为所有能力失效。

## 官方 H3 能力与当前云端 Runtime 的边界

- MiniMax 官方开源仓库是 [`MiniMax-AI/MiniMax-H3`](https://github.com/MiniMax-AI/MiniMax-H3)，模型能力和提示词规范以其当前 `main` 分支、模型卡和 `h3-prompt-writing` 为上游基准；它不是当前 CompShare 插件的代码仓库。
- 官方 H3 的 `Ref2VA` 支持最多 9 张图片、3 段参考视频和 3 段参考音频；每段视频/音频为 2–15 秒，视频/音频总时长不超过 15 秒，混合参考文件总数不超过 12 个。官方 H3 可生成原生音频，完整 2K 流程由 Context-IR、H3-Base 和 Regenerate-2K 组成。
- “官方模型支持参考视频”不等于“当前优云插件支持上传参考视频”。每次生成前必须以当前插件的 `h3-cloud generate --help`、Runtime Profile 和实际上传参数为准；只有明确存在并通过只读输入检查的 `--reference-video` 或等效参数时，才可上传 MP4。否则只能把视频抽帧为图片参考，并明确告知用户这是能力降级。
- 增强版 CLI 提供 1–3 个 `--reference-video`：MP4/MOV、H.264/H.265、23.976–60fps、单段 2–15 秒、单文件不超过 50MiB、总长不超过 15 秒。可和最多 9 张参考图混用，不与首尾帧混用，不复用原音轨。H20 单视频方块动作案例已经实测通过，多素材组合目前只经过本地测试；原版 0.1.0 仍只有参考图输入，不得混淆。
- 模型权重、镜像、Runtime 和参考素材是不同层：用户素材通常由控制端上传到云端 Runtime；模型权重和工作流通常来自平台模型缓存或部署镜像，不会因为调用 Skill 就自动从 Git 仓库上传。不要下载或上传几十 GB 模型，除非用户明确要求并完成成本、许可证和磁盘确认。

公开版不附带任何凭证、实例绑定或生成记录。每位使用者须自行安装官方 CompShare CLI，并通过隐藏输入建立自己的凭证配置；同名 compshare-cli Skill 可用时按其规范操作，没有该 Skill 时仍可使用本包脚本和 CLI 帮助。

## CompShare 执行层

- `minimax-mac-gpu` 是 H3 视频工作流的总控层，拥有素材审查、提示词定稿、费用确认、自动关机、资源删除确认和最终验收的最高流程控制权。
- `compshare-cli` 是 CompShare 的执行层；涉及区域、GPU、镜像、库存、价格、实例、SSH、文件传输、远程任务、磁盘、带宽或 MiniMax H3 任务时，调用官方 `compshare --json` CLI，不自行编写平台 HTTP 请求。
- 所有自动化和状态读取优先使用单一 JSON 输出；遇到不熟悉的命令或参数，先运行 `compshare --json COMMAND --help`，不要猜测参数。
- `compshare-cli` 中的示例不能绕过本 Skill 的素材审查、提示词确认、实时报价和单次付费确认闸门；只有在本 Skill 的流程允许后，才能使用会产生费用的命令及 `--yes`。
- CompShare 命令超时或返回不确定时，先检查实例或任务当前状态，再决定是否重试；已有 `prompt_id` 或幂等键时只恢复原任务，绝不重复提交。

## 选卡和费用确认前：分辨率选择与画面比例确认

适用于所有生成模式。先完成素材审查与提示词，再确认输出规格，随后才进入 GPU 选卡和实时报价。已在本次对话明确的比例、分辨率与时长直接沿用并回显，不重复要求选择；只询问缺项或能力冲突。

1. **展示分辨率选项列表**：依据当前运行器参数和工作流实际能力，列出档位、预计宽×高、对应 MP、支持状态及清晰度/耗时差异。0.2–1.0MP 的基础运行器可提供“快速预览 0.4MP”“均衡 0.6MP”“精细基础版 0.98–1.0MP”。横屏 16:9 历史示例约为 864×480、1056×608、1344×768–1376×768；竖屏必须重新计算或依据实测尺寸，不机械套用横屏标签。示例是近似值，最终尺寸以 ffprobe 为准。
2. **确认画面比例**：展示当前支持的 9:16 竖屏、16:9 横屏、1:1 方形、2:3、3:2、3:4、4:3、21:9。用户要求“原图同比例”时，先按 EXIF 方向计算显示比例；关键帧比例冲突时说明是否裁切、补边或调整画幅，得到选择后再继续。不要把竖向 2:3 默认改为 9:16。
3. **准确标注能力**：MP 是总像素数，不能把 1MP 称为 2K。1080P、2K 只有在当前执行路线支持且有对应工作流时才作为可执行选项；否则明确标为“当前路线不可用/需另外部署”。模型原生生成、二次重生成和普通插值放大分别标注，不静默降低用户要求。
4. **一次汇总确认**：回显“比例、预计宽×高、分辨率档位/MP、时长、声音方案”；缺项可合并询问。规格确定后再按显存需求选卡和计算费用。用户改变分辨率或比例导致成本变化时更新报价；已有有效授权不重复索取。

## GPU 选卡策略：H20 与 A800

- 需要 H20 时选择 `h20-96gb`：H20 96GB 显存、16 CPU、240GiB 系统内存。费用和库存每次刷新；显存与系统内存不能混为一谈。
- 查询实时库存和报价时，必须记录实际型号、显存容量、实例类型（裸机/vGPU/MIG）、CUDA/驱动镜像、区域、小时价和证据状态；不能把未标明显存容量的“A800”默认当作 80GB。
- H20 的真实 CUDA 故障无法修复时，可向使用者提出 A800 备用方案；不得将发布者的历史授权沿用到新使用者。先用 ComfyUI 实际解释器核验 PyTorch、CUDA、设备和小规模运算；系统 Python 缺 torch 不代表 CUDA 故障，驱动 CUDA 上限也不等于 PyTorch 编译版本。只能依据实际错误修复，不盲目升级整套驱动。
- 回退首选 A800 80GB，切换前停止 H20 并刷新 A800 计划；超出授权费用时确认差额。已有 prompt_id 先检查终态并恢复原任务，不能在结果未知时另交同一任务。其他 A800 规格须独立核验，不把更换 GPU 当成完整 2K 或高精度部署已经完成。
- 只有在 A800 无库存、镜像不兼容当前 H3 工作流、A800 报价超出本次费用上限，或用户明确指定 RTX 5090 时，才允许回退到 RTX 5090；回退必须先说明原因，不得静默切换。
- RTX 5090 仅作为量化版 H3 的备用高吞吐方案。若使用 5090，必须确认其驱动/CUDA/PyTorch/ComfyUI 镜像已经支持 Blackwell，并检查是否会因 32GB 显存触发 CPU offload；不能仅因“能启动”就判定配置适合生成。
- 选卡偏好不改变素材审查、提示词确认、实时报价和单次付费确认闸门；GPU 选择必须在只读 `h3-provision plan` 中展示，并纳入用户本次费用确认。

## 接入完成后的制作流程：先审查素材，再写提示词，最后才生成

用户提供素材时，未接入的新使用者先走注册接入流程；接入后仍需按以下顺序推进，不直接创建实例或提交任务：

1. **接收与登记素材**：确认每个文件的绝对路径、文件类型、来源和用户希望扮演的角色；无法判断是首帧、尾帧、关键帧还是普通参考图时先询问，不静默猜测。
2. **素材合规与技术检查**：读取 [references/material-review.md](references/material-review.md)，检查文件可读性、格式、尺寸/比例、文件大小、清晰度、主体完整性、明显水印/平台标识、版权或肖像风险提示，以及是否符合 H3 当前输入限制。视频素材必须先用 `ffprobe` 检查，再按规范抽取代表帧或联系表；图片素材必要时转换为不改变主体内容的工作副本。不得覆盖用户原文件。
3. **素材筛选与分组**：给每份素材标记 `通过`、`有条件通过` 或 `不建议使用`，说明原因；选择实际提交的素材子集，并明确每份素材对应的 `<Picture N>`、`<Subject N>`、首帧/尾帧/参考图角色。关键帧模式与参考图模式不能混用。
4. **严格按 MiniMax Skill 格式生成提示词**：根据筛选结果读取并执行 `prompt-authoring.md`；涉及产品、汽车或新能源内容时同时执行 `product-ad-authoring.md`。必须使用对应模式的固定结构、字段名、素材标签、时间线写法、声音段落和产品锚点规则，不得自行改成普通自然语言提示词、平台自定义格式或混用另一模式的字段。提示词必须引用实际素材映射，不得把未通过审查的素材写进生成参数。将完整提示词保存为 UTF-8 文件。
5. **审查回传、一次修改机会与停顿**：先向用户提交“素材审查结论 + 素材映射 + 完整 MiniMax 格式提示词 + 建议的画幅/时长/清晰度 + 尚待确认项”，并明确这是第 1 版。用户拥有 **一次集中修改机会**，可以一次性提出内容、镜头、动作、声音或参数调整；我必须根据同一份素材审查结果重新输出完整提示词，而不是只给零散差异。第 2 版提交后，提示词进入定稿状态；如仍需重大改动，应重新说明变更范围并重新走审查，不得悄悄进入收费流程。在用户明确确认素材和提示词前，不查询付费创建流程、不创建/启动实例、不提交生成任务。
6. **输出规格、选卡与费用闸门**：用户确认素材和提示词后，先执行上文“分辨率选择与画面比例确认”，规格明确后才进入 GPU 选卡、刷新实时价格/库存并运行只读 `h3-provision plan`；把本次模式、画幅、预计宽×高、时长、清晰度、最新总小时价、预计占用时间和费用上限完整告知用户。只有用户针对这一次明确确认费用，才允许 `create --yes` 或任何会启动收费资源的命令。

如果素材审查发现版权/肖像授权不明、内容不适合生成、清晰度不足、主体被裁切或 H3 不支持该类型，必须停在审查阶段并给出可执行的替代方案；不能用“先生成看看”绕过审查。

工作流严格分为两个阶段：前期提示词生成、后期云端执行。融入的 `h3-prompt-writing` 与 `h3-product-ad` 内容只在前期生成最终提示词，不得查询 GPU、计算费用、创建或启动实例、提交生成任务、下载视频或清理资源，也不改变后期执行参数。提示词定稿后才进入 CompShare 云端流程。

## 不可破坏的边界

- API Key 只由官方 `compshare` CLI 在本机隐藏输入和保存。不要读取、打印、复制或要求用户把密钥发到聊天中。
- 两套提示词资料只负责生成提示词。禁止因其中出现 API、模型或平台说明而改走 MiniMax 官方 API、LibTV 或其他视频生成服务。
- 查询状态、库存和报价可以直接执行。创建、启动或生成会产生费用；必须在最新报价和本次参数已经明确后取得单次付费确认。
- 一次付费确认只授权对应的一次生成。已有 `prompt_id` 时只恢复原任务，绝不重新提交。
- 默认设置 30 分钟兜底关机，并在成功、失败或中断后立即关机。异常退出后必须确认实例状态。
- 生成结束、文件下载和 GPU 关机均验证后，主动报告仍在持续计费的磁盘、镜像或其他资源，并询问用户是否删除实例和关联磁盘。没有明确确认不得删除。
- 用户确认删除后，使用官方 CLI 删除实例及关联收费磁盘，验证资源不存在，再清除本地配置中的旧 `resourceId`。本机视频和项目文件必须保留。
- MiniMax H3 社区许可证存在地域限制。用户明确位于排除地区或授权不确定时，不启动付费资源，先让用户核对完整许可证。

## 完成标准

安装任务只有在环境、插件、凭证、实时选卡、只读部署计划和安全配置全部验证后，才可称为“付费确认后可生成”。生成前必须先完成适用的提示词流程：普通内容使用通用 H3 结构，产品广告增加广告节奏、产品锚点和行业红线。生成任务只有在本地 MP4 可读、时长与分辨率已核对、人物或主体动作经过抽帧检查、GPU 已停止后才可完成。删除任务只有在平台不再返回目标实例且本地配置已清除旧绑定后才可完成。
