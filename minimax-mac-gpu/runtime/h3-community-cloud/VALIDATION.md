# 0.2.1 验证记录

2026-09-07，核心生成代码与 0.2.0-rc.2 保持一致；0.2.1 更新公开版首次引导、相对路径和 CLI 帮助说明。

- 项目测试 24/24、包内 23/23 通过。
- GPU：NVIDIA H20，97871MiB 显存，驱动 595.71.05，MIG Disabled。
- 服务：ComfyUI 0.33.0，Python 3.10.15，PyTorch 2.10.0+cu130；BF16 CUDA 矩阵运算通过。
- 输入：一段 5 秒、640×360、24fps H.264，无音轨，白色方块在蓝色背景匀速向右。
- 模式：Ref2VA，原生 20 步量化工作流，16:9、5 秒、0.2MP、seed 42。
- 实机任务仅提交一次，无恢复重试；公开记录不包含实际任务标识、实例标识或私人日志。
- 输出：608×352、24fps、5.167 秒、H.264、AAC 32kHz 双声道。
- 耗时：上传 387ms、预检 3499ms、提交 118ms、排队及生成 195306ms、下载 216ms。客户端总计 199566ms，不包括外层启动、约数分钟首次缓存校验与关机。
- 按 5fps、160×90 归一化采样：成片 26/26 帧有白色主体，无超过 1 像素的反向位移，垂直中心波动约 0.075 像素。与原参考同方向、位置及大小近似。
- Kimi 对五张代表帧检查：主体持续右移，无明显畸变或重复，未见明确平台/AI 水印。该结论不覆盖未查看的每个像素或所有未来视频。
- 下载成功、GPU 自动停止，随后再次查询确认 stopped。

该案例证明单视频输入、工作流接线、执行、下载、简单动作与关机流程可用。它不是复杂场景质量保证，也没有通过无参考对照来单独测量参考视频的因果贡献。多参考视频/混合图像目前仅本地测试；复杂人物、车辆、高分辨率和完整 2K 仍需独立验收。

此前问题为外层漏传视频参数、视频专用提示词误带 Picture 标签、旧动作素材为空蓝画面；本次没有出现 CUDA 推理故障。H20 上 nvfp4 使用模拟路径是日志事实，不能据此推断比 A800 更快或更慢。
