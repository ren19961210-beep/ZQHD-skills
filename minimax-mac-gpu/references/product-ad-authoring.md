# MiniMax H3 产品广告提示词流程

本流程融入用户指定的 [h3-product-ad](https://github.com/ren19961210-beep/ZQHD-skills/tree/main/h3-product-ad)，只负责云端执行前的产品广告提示词生成。它不得查询 GPU、计算费用、创建或启动实例、提交生成任务、下载视频或清理资源。完整提示词资料已随本 Skill 保存：

- 基础模式指南：[product-ad/base-modes-guide.md](product-ad/base-modes-guide.md)
- Ref2VA 指南：[product-ad/ref2va-guide.md](product-ad/ref2va-guide.md)
- 产品广告模板：[product-ad/product-ad-templates.md](product-ad/product-ad-templates.md)

## 收集产品五要素

1. 品牌和型号的唯一称谓。
2. 外观锚点：颜色、材质、比例、线条和 Logo 位置。
3. 核心卖点，按重要性排序并转成可见动作。
4. 台词、Logo、车名、口号和屏幕文字原文。
5. 时长、画幅和发布平台。

已有信息足够时直接完成，不重复询问。真正影响模式、产品身份或最终画面的缺失信息才询问。

## 广告结构

按目标时长压缩以下六拍：开场钩子 → 产品亮相 → 卖点展示 → 场景体验 → 情感收尾 → 品牌露出。

- 4–8 秒：优先保留钩子、亮相、一个核心卖点和品牌露出。
- 9–12 秒：可增加第二卖点或简短使用场景。
- 13–15 秒：完整展开六拍，但每个镜头仍只承担一个主要信息。

不要为了凑齐六拍牺牲动作连贯性。首尾帧任务通常优先单镜头连续过渡；产品参考图任务把外观一致性放在镜头数量之前。

## 产品与汽车红线

- 产品主体的颜色、材质、比例、Logo、关键线条和屏幕界面不得漂移。
- 新能源汽车画面默认排除烟、蒸汽、火焰、火花和爆炸；充电、换电或能量变化使用干净光影、机械动作和提示音表现。
- 真实参考车辆不自行重新设计，不新增不存在的灯组、格栅、轮毂、车标或车身结构。
- 一个卖点对应一个清晰可见的动作或特写，不用抽象形容词代替证据。
- Logo、口号、车名和界面文字用双引号逐字保留；不要翻译或改写。
- 台词逐字保留在 `<d>[语言] 原文</d>` 中。
- 提示词明确无字幕、无额外标志、无平台或 AI 水印；交付前仍需抽帧检查。

## 输出

先用一句中文说明模式和理由，再给出完整 H3 提示词以及提示词所依赖的素材角色和素材顺序。提示词结构遵循 `prompt-authoring.md`：基础模式使用三个核心字段，Ref2VA 使用固定六段。

完成提示词并写入 UTF-8 临时文件后结束前期阶段。首次输出后给用户一次集中修改机会；修改时必须按相同的 MiniMax H3 广告格式重新输出完整版本，保留模式结构、素材标签、广告节奏、产品锚点和汽车/新能源红线。“写好广告提示词”或用户提出修改意见，均不构成创建云端实例的授权；第 2 版得到用户明确确认后，才进入 [generate-and-cleanup.md](generate-and-cleanup.md)，独立核对执行参数、刷新优云报价并取得单次付费确认。
