# MiniMax H3 素材审查与筛选流程

本文件只负责生成前的本地素材审查，不创建实例、不启动 GPU、不计算或确认云端费用、不提交视频任务。审查的结果必须能让用户看懂并复核，不能只给“可以/不可以”结论。

## 1. 先建立素材清单

对每个用户上传文件记录：

- 绝对路径、文件名、类型、大小、是否能正常读取；
- 图片的像素尺寸、方向、画幅比例、透明通道；
- 视频的编码、实际时长、帧率、分辨率、音视频流；
- 用户期望角色：首帧、尾帧、首尾帧、普通参考图，或仅供分析；
- 作为产品/汽车素材时的车型、颜色、材质、Logo、车身结构等身份锚点。

不要把聊天缩略图当作可供命令行读取的文件。若绝对路径不存在或文件不可读，停下说明缺失，不伪造检查结果。

## 2. 图片检查

优先使用系统可用工具读取图片元数据；必要时用视觉能力逐张查看实际画面。检查：

- 主体是否完整、清晰、无遮挡，是否存在严重压缩、过曝、欠曝或运动模糊；
- 主体在画面中的位置和朝向是否支持目标动作；
- 画幅是否适合用户目标平台，是否需要裁切；
- 是否有明显平台水印、AI 生成水印、无关 Logo、字幕或不应保留的文字；
- 汽车是否为同一真实车型，不能自行补画灯组、格栅、轮毂、车标或车身结构；
- 是否包含第三方人物、品牌、车辆或私人信息，并提醒授权/隐私风险。

如果需要调整尺寸、方向或格式，只生成新的工作副本，保留原图。不得为了“合规”擦除水印、改造车身、替换 Logo 或改变主体身份；这类问题应标为不建议使用并请用户提供合规原图。

## 3. 视频检查与抽帧

先用 `ffprobe` 读取真实视频流信息，再按总时长抽取开头、四分之一、中点、四分之三和结尾附近的代表帧；短视频至少抽取 3 帧。抽帧文件写入独立临时目录，不覆盖原视频。

审查代表帧和必要的联系表：

- 主体身份、颜色、材质和背景是否跨时间稳定；
- 是否出现水印、字幕、平台标识、人物/车体畸变、重复帧、黑屏或突变；
- 动作是否连续，是否适合作为参考节奏/风格，而不是误当作当前 Runtime 支持的视频输入；
- 音频是否存在及是否需要保留。增强版可接收视频画面参考，默认不接原音轨；当前尚无参考音频 CLI。

参考视频本地合同：1–3 段 MP4/MOV，H.264/H.265，23.976–60fps，单段 2–15 秒、50MiB 以内，总时长不超过 15 秒。必须抽帧检查：本项目旧 motion 测试文件曾只有蓝色背景，文件名不能证明存在动作。

## 4. H3 角色与模式筛选

先区分“官方 MiniMax H3 能力”和“当前优云插件实际输入能力”。官方 Ref2VA 可接收图片、视频和音频参考，但当前 CompShare Runtime 是否能接收视频，必须以当次插件帮助和 Runtime Profile 为准；不能仅凭官方模型仓库的说明上传 MP4。

先根据用户意图选择唯一模式：

- 图片必须成为视频起点：`I2VA`，提交 `--first-frame-image`；
- 图片必须成为视频终点：`L2VA`，提交 `--last-frame-image`；
- 有首尾两张锚点：`FL2VA`，同时提交首帧和尾帧；
- 图片只用于保持主体/场景/风格：`Ref2VA`，每张使用一次 `--reference-image`，最多 9 张；
- 视频只用于保持动作/主体/场景：仅当当前插件明确提供并验证了参考视频参数时，才使用 Ref2VA 视频输入；否则先用 `ffprobe` 检查，再抽取代表帧作为图片参考，并把“视频未直接上传”写入审查结论；
- 没有图片且无视频参考：`T2VA`。

关键帧参数与参考素材参数互斥。若用户只说“用参考图”，但没有说明图片是否必须成为首帧或尾帧，先询问用途。

## 5. 审查报告格式

在提示词生成前先输出简明但完整的审查报告：

```text
素材审查结论：通过 / 有条件通过 / 暂停

| 素材 | 检查结果 | 建议角色 | 使用方式 | 风险或需要补充 |
|---|---|---|---|---|

模式判断：I2VA / L2VA / FL2VA / Ref2VA / T2VA
实际提交素材：...
不使用素材：...
需用户确认：...
```

随后生成完整 H3 提示词，并列出提示词中的 `<Picture N>`、`<Subject N>` 与本地文件的对应关系。只有用户确认审查结果和提示词后，才进入 `generate-and-cleanup.md` 的实时报价和付费流程。
